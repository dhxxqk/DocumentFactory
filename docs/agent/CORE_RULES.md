# CORE_RULES.md — 核心规则（最高优先级）

适用范围：所有 Agent、所有任务。本文件是 `docs/agent/` 治理层中优先级最高的规则；专项规则与本文件冲突时，以本文件为准。

## 1. 项目事实源

```text
GitHub Repository is the single source of truth.
```

- 不以聊天记录作为事实
- 不以个人记忆或跨会话印象作为事实
- 不以任务描述中的背景陈述作为事实
- 必须检查仓库当前状态：`git status` / `git log`、实际代码、测试、已存在的任务书与开发报告

当任务书与仓库事实冲突时，**暂停执行并向任务提出者确认**，不得自行选择对自己方便的解释，也不得默默沿用错误前提。冲突内容与裁定结果必须写入开发报告。

## 2. 开发原则

### 2.1 修改前：Understand before modify

```text
读取任务
  ↓
检查仓库（git 状态、相关代码与测试、既有任务/报告）
  ↓
定位影响范围
  ↓
制定方案
  ↓
实施
```

动手写代码前必须能够回答：任务编号是否已被占用？要改哪些文件？相关行为当前由哪里实现？现有测试覆盖了什么？

### 2.2 修改过程中

禁止：

- 无需求重构（任务范围外的重写、改名、搬家、风格统一）
- 删除已有功能或弱化既有校验、severity 与检查项
- 修改测试期望、跳过或删除测试用例来绕过失败
- 引入未验证的新依赖
- 修改与任务无关的模块
- 覆盖原始输入文件
- 提交运行生成物、临时文件与个人配置
- 绕过 DocumentFactory Core，由 Agent 直接修改 OOXML（产品级红线，见 ADR-001）

要求：

- 发现问题先记录，再决定是否继续
- 小步修改，保持既有架构分层：入口层（CLI / MCP / Agent 集成）为薄适配，业务逻辑只在 Core
- 只处理可确定对象；不确定对象保留原状并进入报告，不靠猜测"修复"

### 2.3 完成后

必须同时交付以下四项，缺一不算完成：

```text
代码修改（如任务涉及）
+ 测试结果（真实命令与输出摘要）
+ Git diff 自检（确认改动范围与任务一致）
+ 开发报告（按 REPORTING_STANDARD.md）
```

## 3. 范围与诚实

- 只做任务书要求的事，不做"顺手"改进；任务外发现的问题记入报告的 Next Suggestion，不直接动手
- 不把条件性通过（测试 skip、缺少渲染后端、缺少外部凭据）报为完全通过
- 剩余风险、未验证项、环境限制必须如实列出
- 报告中的数字、哈希、路径、命令输出必须来自实际执行，禁止编造或估算填充

## 4. 规则优先级

1. 仓库事实与任务书显式约束（两者冲突时先确认，见第 1 节）
2. 本文件 CORE_RULES
3. `docs/agent/` 其余专项规则
4. 既有项目文档（`README.md`、`docs/ADR_001_*`、`CHANGELOG.md`）
5. 个人或工具经验：仅在前述来源都不覆盖时参考，且需在报告中说明依据
